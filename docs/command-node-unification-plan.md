# План унификации узлов Command

Статус: реализация начата; каталог и схемы операций готовы.

## Проблема

Текущий узел `command` скрывает разнородные специализированные операции за строковым идентификатором и необъяснённым JSON. Многие команды неявно зависят от конкретных шагов, структуры trigger и результатов предыдущих сценариев. Поэтому их трудно безопасно использовать при создании нового flow.

Специализированные операции допустимы, но они должны иметь явный контракт и категорию, а не выглядеть как универсальные команды.

## Целевая модель

Разделить каталог на три уровня:

1. Универсальные узлы: Condition, Set/Transform, Loop, Delay, HTTP Request, Merge, Terminal.
2. Интеграционные операции: Gitea Create Pull Request, Plane Update Issue, Test Runner Run Tests.
3. Переиспользуемые subflow-компоненты: Verify Bug Report, Prepare and Test Change, Bug-finding Pipeline.

Каждая операция должна публиковать:

- стабильный идентификатор и версию;
- понятное название и описание;
- `input_schema` и `output_schema`;
- обязательные интеграции и capabilities;
- возможные outcomes и ошибки;
- примеры конфигурации;
- ссылку на executor.

## Передача данных

Убрать поиск данных по неявным именам шагов внутри executor. Связи задаются явно, например:

```text
find-bugs.output.bug_report
        -> verify-report.input.report
```

UI проверяет совместимость портов и строит форму параметров по схеме. Редактирование сырого JSON остаётся расширенным режимом.

## Переработка текущих команд

- `complete` и `fail` заменить terminal-узлами.
- `allow_test_rewrite` и `allow_bug_rewrite` заменить Loop + Condition.
- `classify_test_run` выразить через Condition.
- `store_failure_report` выразить через Set/Transform.
- `sync_plane_issue` оформить как операцию Plane.
- `create_final_pull_request` оформить как операцию Gitea.
- `execute_test_change` оформить как операцию Test Runner или составной subflow.
- `verify_bug_report` оформить как версионируемый составной компонент.

persisted input snapshot `NodeRun`; вложенные пути объединяются со статической конфигурацией без
`eval` и повторно не вычисляются при retry.

## Критерий результата

Пользователь может собрать новый сценарий, не зная внутреннего Python-кода, а UI заранее показывает необходимые входы, результаты, интеграции и ошибки каждого узла.

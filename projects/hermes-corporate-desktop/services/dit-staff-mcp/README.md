# DIT Staff MCP

## Детальный план адаптации

- `staff_list_my_adaptation_plans` возвращает назначенные текущему пользователю планы;
- `staff_list_my_adaptation_stages` возвращает этапы, разделы, статусы, сроки и описания выбранного плана;
- навигация к плану выполняется только через GET, а таблица этапов загружается фиксированным read-only запросом `doaction=Grid`.

Локальный MCP-сервер только для чтения корпоративного портала `https://staff.mos.ru` (Mirapolis Cloud).

## Возможности первой версии

- профиль текущего пользователя и сводка главной страницы;
- перечень разделов, доступных в меню пользователя;
- ограниченное чтение содержимого выбранного раздела;
- назначенное и завершённое обучение;
- сертификаты пользователя.

Сервер не содержит методов изменения профиля, регистрации на мероприятия, прохождения курсов и тестов,
комментирования, загрузки, удаления или скачивания файлов. Навигация выполняется через GET. Внутренний интерфейс
Mirapolis загружает строки таблиц запросом POST `doaction=Grid`; MCP разрешает только этот фиксированный read-only
запрос и не принимает название действия от модели.

## Авторизация через СУДИР

Основной вариант не запрашивает и не сохраняет пароль СУДИР:

```powershell
.\.venv\Scripts\dit-staff-mcp.exe --authorize-sudir
```

Откроется отдельное изолированное окно Microsoft Edge. После входа помощник сохраняет в Windows Credential Manager
только cookies домена `staff.mos.ru`; cookies `sudir.mos.ru`, пароль и профиль обычного браузера не копируются.
Полученная сессия проверяется чтением собственного профиля.

## Альтернативная авторизация Mirapolis

Если администратор выдал отдельный системный логин Mirapolis, API принимает эти учётные данные и возвращает временный `access_token`. MCP хранит токен
только в памяти процесса и переоткрывает сессию после истечения срока. На Windows сохраните отдельную запись в
Credential Manager интерактивной командой:

```powershell
.\.venv\Scripts\dit-staff-mcp.exe --save-credentials
```

Сначала сервер проверяет вход чтением собственного профиля и только после успеха сохраняет пароль в системном
хранилище с именем `DIT-Agent/Staff`. Альтернативный вариант для среды без Windows Credential Manager:

```powershell
$env:DIT_STAFF_LOGIN = '<логин staff.mos.ru>'
$env:DIT_STAFF_PASSWORD = '<пароль staff.mos.ru>'
```

Переменные окружения имеют приоритет над Credential Manager. Не добавляйте пароль в YAML, аргументы командной строки
или репозиторий. Учётные данные Outlook автоматически не
используются: для портала должен быть отдельный секрет, даже если фактически пароль совпадает.

## Установка для разработки

```powershell
.\.venv\Scripts\python.exe -m pip install -e .\services\dit-staff-mcp
```

## Проверка соединения

```powershell
.\.venv\Scripts\dit-staff-mcp.exe --doctor
```

Команда выполняет вход и читает только профиль текущего пользователя. Пароль и токен в вывод не попадают.

## Подключение к DIT Agent

Скопируйте сервер `dit_staff` из `config.example.yaml` в `mcp_servers` изолированного профиля. Секреты сохраните в
его `.env`, затем создайте новую сессию DIT Agent, чтобы набор инструментов оставался стабильным весь разговор.

Если провайдер модели должен работать через системный прокси, а `staff.mos.ru` напрямую, добавьте домен в
`NO_PROXY`. Параметр `--no-env-proxy` отключает переменные прокси только внутри данного MCP-процесса.

## Ограничения безопасности

- наружу опубликован только фиксированный набор read-only операций портала;
- произвольный URL, `doaction` или навигационный токен передать через MCP нельзя;
- `access_token`, `usrsesid`, пароли и ключи удаляются из ответов;
- HTML превращается в обычный текст, длинные поля и ответы обрезаются;
- тексты портала считаются недоверенными данными, а не инструкциями для агента;
- пагинация ограничена максимум 50 объектами по умолчанию (настраивается, предел API — 200).

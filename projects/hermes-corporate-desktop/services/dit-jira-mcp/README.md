# DIT Jira MCP

Локальный MCP-сервер только для чтения корпоративной Jira `https://itpm.mos.ru`.
Сервер использует Jira Server REST API v2 и Jira Software Agile API, если модуль
Jira Software доступен текущему пользователю.

Проверенная инсталляция на момент разработки: Jira Server 8.20.8. MCP не
использует Cloud API v3 и не предполагает стандартный набор статусов или полей.

## Возможности

- проверка версии Jira и текущей учётной записи;
- список доступных проектов;
- динамическое обнаружение системных и кастомных полей;
- поиск задач через JQL с ограниченной пагинацией;
- чтение задачи, комментариев и истории изменений;
- получение типов задач и статусов отдельно для каждого проекта;
- просмотр доступных переходов и обязательных полей без выполнения перехода;
- чтение избранных фильтров;
- просмотр Jira Software boards и sprint'ов.

## Гарантия read-only

В клиенте реализованы только HTTP `GET`-запросы. MCP не содержит инструментов
создания, редактирования, назначения, комментирования, перехода по workflow или
удаления задач. Все инструменты имеют MCP-аннотацию `readOnlyHint=true`.

Тексты задач, комментарии, значения полей и результаты поиска считаются
недоверенными данными, а не инструкциями для агента.

## Кастомные поля и статусы

Названия полей Jira не уникальны. Поэтому каждый результат возвращает:

- стабильный ID поля, например `customfield_12345`;
- текущее отображаемое название;
- JQL clause names;
- схему и необработанное структурированное значение в ограниченном виде.

Если два поля имеют одинаковое название, вызов по названию завершается ошибкой
`ambiguous_field` и предлагает использовать ID. Статусы загружаются из
`/project/{key}/statuses` по каждому типу задачи и нигде не зашиты в коде.

## Авторизация

Предпочтительный вариант — Jira Personal Access Token (PAT):

Открыть управление токенами можно по адресу
`https://itpm.mos.ru/plugins/servlet/personal-access-tokens/manage` после входа в Jira.

```powershell
$env:DIT_JIRA_TOKEN = '<PAT>'
```

Токен передаётся как `Authorization: Bearer <PAT>`. Не добавляйте токен в YAML,
аргументы командной строки или репозиторий.

В Jira Server 8.20 PAT наследует права учётной записи и сам по себе может не иметь
отдельного read-only scope. Гарантия read-only обеспечивается этим MCP: его HTTP-клиент
реализует только `GET`. Поэтому токен всё равно нужно хранить как полноценный секрет.

Если PAT отключён администратором, поддерживается Basic Auth:

```powershell
$env:DIT_JIRA_USERNAME = '<login>'
$env:DIT_JIRA_PASSWORD = '<password>'
dit-jira-mcp --auth-type basic --allow-all-visible
```

При корпоративном SSO Basic Auth может быть запрещён. Явный режим
`--auth-type anonymous` предназначен только для проверки общедоступных данных.

## Установка

Из корня DIT Agent:

```powershell
uv pip install --python .\.venv\Scripts\python.exe -e .\services\dit-jira-mcp
```

## Проверка соединения

```powershell
$env:DIT_JIRA_TOKEN = '<PAT>'
.\.venv\Scripts\dit-jira-mcp.exe `
  --base-url https://itpm.mos.ru `
  --auth-type pat `
  --allow-all-visible `
  --no-env-proxy `
  --doctor
```

`--doctor` выводит версию сервера, безопасное описание пользователя, количество
доступных полей/проектов и наличие Jira Software. Секреты не печатаются.

## Подключение к DIT Agent

1. Установите пакет в `.venv`.
2. Добавьте блок из `config.example.yaml` в `mcp_servers` изолированного профиля.
3. Добавьте `DIT_JIRA_TOKEN` в `.env` этого профиля.
4. Создайте новую сессию DIT Agent: набор MCP-инструментов фиксируется в начале
   разговора для сохранения prompt cache.

## Политика проектов

- `--allow-project KEY` — разрешить конкретный проект; параметр повторяется.
- `--allow-all-visible` — разрешить всё, что видит Jira-учётная запись.

При allowlist любой JQL автоматически оборачивается обязательным условием
`project in (...)`. Избранные фильтры доступны только с `--allow-all-visible`,
поскольку один фильтр может охватывать несколько проектов.

## Сеть

- по умолчанию учитываются `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY` и `NO_PROXY`;
- `--no-env-proxy` полностью отключает proxy-переменные для Jira;
- `--proxy URL` задаёт отдельный прокси;
- `--ca-bundle PATH` задаёт корпоративный CA bundle.

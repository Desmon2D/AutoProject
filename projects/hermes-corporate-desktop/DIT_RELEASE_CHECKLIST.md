# Подготовка DIT Agent к GitHub

## До создания репозитория

- Определить видимость репозитория. При отсутствии разрешения на публикацию
  корпоративных доменов, API-контрактов и бренда использовать private repository.
- Подтвердить допустимость передачи корпоративных данных в OpenRouter или другой
  внешний inference endpoint.
- Сохранить `LICENSE` и `NOTICE`: проект является производной работой Hermes
  Agent под лицензией MIT.
- Проверить право использования названия и изображения DIT Agent.
- Не включать `.env`, токены, cookies, данные Windows Credential Manager,
  содержимое `%LOCALAPPDATA%\hermes-corporate-dev` и `.runtime`.
- Запустить secret scanning по рабочему дереву и истории перед первым push.
- Если секрет когда-либо попадал в commit, удалить его из истории и обязательно
  отозвать/перевыпустить сам секрет.

## Git-настройка

Публичная копия поставляется как каталог
`projects/hermes-corporate-desktop` монорепозитория `Desmon2D/AutoProject`.
Вложенный `.git` из рабочего downstream-репозитория не переносится: в
монорепозиторий добавляется очищенный снимок файлов. История и remote
`NousResearch/hermes-agent` остаются только в локальном downstream checkout,
который используется для получения upstream-обновлений.

Перед push проверьте изменения из корня `AutoProject` и убедитесь, что среди них
нет `.env`, профилей `%LOCALAPPDATA%`, cookies, токенов и runtime-логов.

## Перед релизом приложения

- Заменить development identity на стабильный publisher identity и подписать
  Windows installer.
- Проверить installer на чистой Windows 10/11 без локальных исходников и venv.
- Добавить UI-настройку корпоративных источников; сейчас часть подключения
  выполняется через локальные конфиги и Windows Credential Manager.
- Зафиксировать поддерживаемую версию upstream Hermes и процесс переноса его
  security fixes.
- Добавить автоматические проверки MCP, сборки desktop и отсутствия секретов в
  CI собственного репозитория.

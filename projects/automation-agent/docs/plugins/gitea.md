# План интеграции с Gitea

Источник требований: [полное описание архитектуры](../architecture.md), разделы 5.3, 8, 14 и 18.

## Работа агента

1. Агент получает задачу.
2. Создаёт или использует рабочую ветку.
3. Изменяет код.
4. Создаёт фиксацию изменений.
5. Отправляет изменения в Gitea.
6. Создаёт или обновляет запрос на слияние.
7. Возвращает ссылку на запрос на слияние в результате шага.

## Проверка изменений

После завершения агента процесс переходит к шагу `review` и ожидает действия пользователя в Gitea.

- Принятие изменений завершает шаг с `COMPLETED + SUCCESS`.
- Требование доработки завершает шаг с `COMPLETED + FAILURE`.
- При `FAILURE` оркестратор формирует новый контекст с комментариями пользователя и возвращает процесс к шагу агента, если это предусмотрено графом.
- Финальное принятие изменений выполняет пользователь.

## Защита от повторов

Повторная техническая попытка не должна создавать несколько одинаковых запросов на слияние, если предыдущая попытка уже успела создать запрос.

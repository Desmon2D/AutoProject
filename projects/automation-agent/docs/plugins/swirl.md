# План интеграции со SWIRL

Источник требований: [полное описание архитектуры](../architecture.md), разделы 11, 13 и 18.

## Назначение

SWIRL используется как единая точка федеративного поиска по корпоративным источникам, включая Jira, Confluence и другие корпоративные системы.

В локальной разработке BookStack используется как аналог Confluence и подключается к SWIRL отдельным поставщиком поиска. Агенты и оркестратор не обращаются к BookStack напрямую. При переходе на Confluence меняется поставщик SWIRL, а не договор расширения и не логика сценариев.

На устройствах с малым объёмом памяти допускается лёгкий SWIRL-совместимый сервис по локальным JSON-документам. Он используется для разработки сценариев, сборщика контекста и расширения агента. Полный SWIRL с Redis запускается отдельно только для проверки настоящей интеграции.

Агент обращается к SWIRL через соответствующее расширение и не реализует отдельную интеграцию с каждым источником.

Результаты поиска через SWIRL содержат стабильный идентификатор документа. Сборщик контекста
выполняет исходный и короткие тематические запросы, объединяет их взвешенным Reciprocal Rank
Fusion и использует штатный endpoint SWIRL `fetch-document`, чтобы получить полный текст лучших результатов
в доверенный слой. Текст делится по Markdown-разделам и абзацам; в начальный контекст попадают
только прошедшие порог релевантности фрагменты в пределах общего бюджета. Сводка покрытия терминов
отдельно контролирует главную тему запроса. Документы и фрагменты с её прямыми подтверждениями
получают приоритет, а отрицательные инструкции пользователя исключаются из поисковых терминов.
Полный документ остаётся доступен через
`swirl_fetch_document`. Оркестратор и агент не получают учётные данные исходной системы и не
обращаются к BookStack напрямую. Допустимые адреса источников ограничены
`SWIRL_CONTENT_ALLOWED_ORIGINS`. Безопасное соответствие имени источника, идентификатора
провайдера и шаблона URL передаётся отдельно через `SWIRL_CONTENT_ROUTES_JSON`; runtime не читает
административный каталог провайдеров SWIRL и не видит заголовки авторизации источников.

## Обработка ошибок

Временная ошибка SWIRL является техническим `ERROR` и обрабатывается правилами повторных попыток. Она не является бизнес-результатом `FAILURE`.

Качество выдачи проверяется без модели командой
`python -m automation_orchestrator.retrieval_eval evals/bookstack-retrieval.json`.

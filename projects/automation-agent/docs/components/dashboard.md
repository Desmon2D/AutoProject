# План панели состояния

Источник требований: [полное описание архитектуры](../architecture.md), разделы 2.1, 17 и 18.

Панель состояния является логическим модулем монолитного оркестратора.

Оркестратор предоставляет через неё состояние выполнения процессов.

## Состояние реализации

- [x] Состояние служб, процессов, шагов и технических ошибок.
- [x] Просмотр входов, выходов и артефактов выполнения.
- [x] Действия проверки, отмены и ручного повтора процесса.
- [x] Read-only Flow Builder для встроенных сценариев: палитра типов, граф переходов и инспектор конфигурации узла.
- [x] Schema-driven настройка всех узлов из backend-каталога, включая retry, списки,
  типизированные параметры операций и input bindings.
- [x] Соединение узлов мышью через входные и выходные порты, локальные undo/redo.
- [x] Подробная backend-валидация и ручной запуск последней опубликованной версии.
- [x] Создание пустого workflow без копирования встроенного сценария.

Flow Builder получает данные из `GET /v1/flows`, `GET /v1/node-types`,
`GET /v1/operations`, `GET /v1/models`, `GET /v1/plugins` и `GET /v1/credentials`. Встроенный
сценарий можно скопировать в пользовательский draft, изменить его название и описание,
перемещать, добавлять и удалять узлы, редактировать настройки и переходы,
проверить и опубликовать. Исходные JSON-сценарии и текущий путь исполнения workflow не
изменяются.

Редактор вынесен из панели мониторинга на отдельный маршрут `/flows`. Dashboard показывает
каталог и открывает выбранный workflow в этом рабочем пространстве. В редактируемом draft новый
узел создаётся перетаскиванием типа из левой палитры на нужную точку холста; кнопка `+` не
используется. Связь создаётся drag-and-drop: при удержании выходного порта `EVENT`, `SUCCESS` или
`FAILURE` временная линия следует за указателем, а связь фиксируется только после отпускания на
входе целевого узла. Изменения графа можно локально отменять и возвращать через undo/redo до
сохранения. Встроенный Trigger остаётся единственным и повторно не добавляется.

Кнопка `Пустой workflow` создаёт независимый draft без узлов и переходов. На пустой холст сначала
можно перетащить единственный Trigger, затем произвольный набор исполняемых, управляющих и
терминальных узлов.

После сохранения граф можно проверить backend-валидатором: полный список ошибок и предупреждений
показывается под редактором. После публикации последняя версия запускается с `/flows`; входные
данные задаются JSON-объектом в поле `Inputs JSON`, без редактирования файла сценария.

Для Trigger инспектор показывает поддерживаемые источники `manual`, `webhook`, `gitea`, `plane`.
Событие всегда выбирается из списка для текущего источника; произвольный ввод запрещён и в UI, и
backend-валидацией. Command выбирает allowlisted-операцию и получает форму её параметров из схемы.
Agent выбирает модель и плагины из каталогов. Agent и Review могут хранить только безопасную
`credential_id`; токены в JSON flow не передаются.

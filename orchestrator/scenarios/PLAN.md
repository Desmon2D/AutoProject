# План сценариев

Источник требований: [полное описание архитектуры](../../00_full_agent_architecture.md), разделы 2–7 и 16.

## Контракт сценария

Сценарий описывается в JSON и содержит:

- тип исходного события;
- начальный шаг;
- набор шагов;
- тип и параметры каждого шага;
- необходимые расширения;
- правила технических повторных попыток;
- переходы по `SUCCESS` и `FAILURE`.

Поддерживаются ровно три базовых типа шага:

- `command` — выполнение заранее определённой команды;
- `agent` — запуск агента в Docker-песочнице;
- `review` — ожидание решения пользователя.

Сценарий является ориентированным графом и может содержать циклы. Технический `ERROR` обрабатывается повторной попыткой и не является переходом по ветке `FAILURE`.

## Сценарий `implement-ticket`

Концептуальный сценарий из полного плана:

1. Событие системы задач запускает шаг реализации: в целевой среде это Jira, в локальной разработке — Plane.
2. Шаг агента использует расширения Git, Gitea, SWIRL и Python.
3. При `SUCCESS` процесс переходит к проверке запроса на слияние в Gitea.
4. При `FAILURE` процесс переходит к сохранению отчёта о неуспешном результате.
5. Принятие изменений завершает проверку с `SUCCESS`.
6. Требование доработки завершает проверку с `FAILURE` и возвращает процесс к реализации.
7. Одобрение завершает процесс как `COMPLETED / SUCCESS`, а ветка неуспешной реализации — как
   `COMPLETED / FAILURE`; сообщение об одобрении не используется для ветки отказа.

Текущий исполняемый вариант сценария принимает событие `plane.issue.ready_for_development`. При подключении Jira меняется входной адаптер и сопоставление события, а не логика графа.
